# 모바일 앱 출시 · 수익화 로드맵

| 단계 | 내용 | 상태 |
| --- | --- | --- |
| 1 | PWA: PC·휴대폰 설치, 오프라인, 자동 업데이트 | 완료 |

## Capacitor로 앱 만들기

웹앱(`app/`)을 그대로 네이티브 앱 안에 넣는 방식이라 코드를 다시 짤 필요가 없습니다.

```bash
npm install
npx cap add android          # android/ 폴더 생성 (Android Studio 필요)
npx cap add ios              # ios/ 폴더 생성 (Mac + Xcode 필요)
npm run cap:sync             # app/ 변경 사항을 네이티브 프로젝트로 복사
npm run cap:android          # Android Studio에서 열기 → 서명된 AAB 빌드 → Play Console 업로드
```

- 앱 ID는 `capacitor.config.json` 의 `appId`(`com.taxcheck.app`)입니다. 스토어에 한 번 올리면 바꿀 수 없으니, 본인 도메인 기반(예: `kr.<도메인>.taxcheck`)으로 먼저 정하세요.
- 앱 안의 Google 로그인은 웹 팝업이 막힐 수 있어 `@capacitor-firebase/authentication` 플러그인으로 네이티브 로그인을 붙이는 것을 권장합니다. 이메일 로그인은 그대로 동작합니다.
- 알림은 `@capacitor/local-notifications` 로 매달 정해진 날 로컬 알림을 예약하면 서버 없이 됩니다.

### 스토어 앱도 재설치 없이 업데이트하려면

| 방식 | 장점 | 주의 |
| --- | --- | --- |
| **라이브 업데이트** (Capgo, Capawesome Live Update 등) | 웹 코드(JS·CSS·세법 수치)를 스토어 심사 없이 배포 | 네이티브 플러그인 추가 시에는 스토어 업데이트 필요 |
| `server.url` 로 배포 주소를 직접 로드 | 웹 배포 = 앱 업데이트, 가장 단순 | 오프라인 첫 실행 불가, Apple 심사에서 "웹 래퍼"로 반려될 위험 |
| 스토어 업데이트만 | 단순 | 매번 심사(수 시간~수 일) |

권장: **라이브 업데이트**. 앱의 핵심 기능을 바꾸지 않는 웹 코드 업데이트는 Apple·Google 정책상 허용됩니다.

## 수익화 모델

신뢰가 중요한 금융 앱이므로 **핵심 계산은 무료**로 두고, 편의·심화 기능을 유료로 하는 프리미엄 모델을 권장합니다.

| 무료 | 프리미엄 (예: 월 2,900원 / 연 19,900원) |
| --- | --- |
| 월별 입력, 한도 진행률, 연금 권장액, 카드 최적화 | 맞벌이 부부 공제 배분 시뮬레이션 (누가 카드·의료비를 몰아받을지) |
| 기기 동기화 | 여러 해 비교, 경정청구(5년) 놓친 공제 찾기 |
| 월간 알림 | PDF 리포트 (회사 제출용 체크리스트) |
| | 영수증 사진 OCR 입력, 카드사 문자/엑셀 자동 분류 |
| | 가족(부모님 등) 부양가족 최적 배분 |

- **결제**: 스토어 인앱결제(구독)를 쓰고, RevenueCat을 붙이면 Android·iOS·웹 구독 상태를 한 곳에서 관리할 수 있습니다. 구독 상태는 Firestore `users/{uid}` 에 저장해 PC에서도 프리미엄이 적용되게 합니다.
- **광고**: AdMob 배너는 쉽지만 금융 앱 신뢰도를 떨어뜨립니다. 넣더라도 무료 사용자에게 결과 화면 하단 정도로 제한하세요.
- **제휴**: 연금저축·IRP 계좌 개설 제휴 수수료는 매력적이지만, 금융상품 광고·중개에는 「금융소비자보호법」 규제가 적용됩니다. 법률 검토 후 진행하세요.
